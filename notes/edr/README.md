# EDR：技术发展史、核心原理与工程落地（1980s—2026）

> **核心结论**：EDR不是单一算法，而是持续采集终端遥测、关联行为、检测攻击并响应的体系。演进主线是 **识别文件 → 监控操作 → 留下历史 → 关联攻击活动 → 自动调查与受控处置**；这些能力长期共存。
>
> **历史口径**：章节是工程重点的大致区间，不是发明年份。早期杀毒、HIPS属于技术前史；统计基线、关联和自动响应都早于LLM。2026是本次整理时间，不代表下列能力都在2026首次出现，也不把没有资料的“最新能力”写成史实。
>
> **阅读方式**：主线解释痛点与迭代；[28节点DAG](history-dag.md)解释依赖；[原子笔记索引](knowledge-index.md)进入实现；[实验目录](experiments/README.md)提供实际源码、输入和验证范围。历史产品事实、现代教学重建、未运行接口片段分别标注。

## 一、演进总览

| 阶段 | 当时的痛点 | 增加的实现 | 工程落地 | 尚未解决 |
|---|---|---|---|---|
| 1980s—1990s | 已知感染需要批量识别 | 字节比较、掩码、共享匹配状态、格式定位 | 扫描引擎与特征库 | 变种、隐藏明文、未知样本 |
| 1990s—2000s | 多态与混淆改变磁盘字节 | 静态规则、CPU解释器、完整系统动态观察、运行时策略 | 模拟扫描、沙箱、HIPS | 环境/路径覆盖、误阻断、历史证据不全 |
| 2000s—2013 | 找到单个文件仍不知道影响范围 | 远程现场采集、IOC条件、部分产品持续记录 | 取证Agent、全网复查 | 快照看不到已消失的过程 |
| 2013—2016 | 企业终端数据碎片化 | 常驻采集、实例身份、队列、留存与索引 | EDR平台与远程调查 | 丢失、成本、误关联 |
| 2016—2020 | 合法工具与动态脚本难判断 | 宿主送检、序列状态、可交换规则、学习模型 | AMSI、狩猎、行为检测 | 误报、漂移、解释与覆盖 |
| 2020—2023 | 人工响应慢、跨域证据割裂 | 调查工作流扩展、任务确认、实体映射、Linux采集改进 | AIR/XDR与运行时传感器 | 处置业务风险、跨域因果不确定 |
| 2023—2026 | 读证据和选查询耗费人力 | LLM组织证据、有约束的多步工具调用 | 调查助手与专门Agent | 幻觉、提示注入、越权和错误处置 |

**历史标志**：2013年7月，Anton Chuvakin使用“Endpoint Threat Detection & Response”命名一类已有产品；命名不等于所有相关技术在当天诞生。[命名原文](https://chuvakin.blogspot.com/2013/07/named-endpoint-threat-detection-response.html)。

## 二、特征码杀毒（1980s—1990s）

**痛点**：同一病毒感染不同宿主，需要低成本、可重复识别。宿主文件整体不同，病毒部分可能仍有共同字节。

**原理**：从已知样本提取稳定片段，在文件候选位置逐字节比较；掩码跳过允许变化的位置，多模式算法共享已经读取的前缀/后缀，格式解析把检查限制在有意义的区域。文件摘要识别相同完整文件，不等同家族片段匹配；MD5的RFC发布于1992年，不能倒填为1980年代标准做法。

```text
样本分析 → 特征与匹配位置 → 扫描器读取 → 比较 → 保存命中证据 → 处置
```

**实际例子**：人工模式`B8 ?? ?? CD 21`可匹配`B8 FF 00 CD 21`，不能匹配`B8 FF 00 CD 10`。文件分块为`xxAB`和`Cyy`时，分别扫描会漏掉ABC；保留前块末尾的必要字节才能跨块匹配。完整逻辑、输入输出与测试见[特征扫描](signature-scanning.md)。

**落地**：按需或驻留触发读取、特征库更新、按文件格式选择候选区域，再按产品策略拒绝/隔离/修复。识别只是第一步；修复寄生病毒还需恢复宿主入口与原始内容。DOS COM与后来PE/ELF的结构不同，不能用同一套节表解析说明所有早期扫描器。

**局限与下一步**：磁盘上只有加密内容时，再快的明文匹配也看不到解密结果。这推动结构启发式和模拟执行，而不是简单淘汰特征码。

## 三、启发式、沙箱与 HIPS（1990s—2000s）

### 3.1 静态启发式：从已知字节到可疑结构

**痛点**：新变种到达时还没有专门特征。启发式可以根据结构和指令组合提出可疑线索，规则/布尔组合/评分都可实现，不一定使用机器学习。

一个DOS COM教学思路是：可信旧文件512字节，新文件640字节，开头变成`E9 FD 01`；相对位移509，加下一指令位置3，跳到文件偏移512，恰好进入新增区域。这是“入口改变并跳入新增内容”的结构信号，不是已确认病毒；合法补丁也可能改变布局。PE节区熵、权限和导入表是另一种格式下的例子，不能混称同一时代的统一特征集。

**落地与例子**：[启发式原理](heuristic-detection.md)、[PE文件基础](pe-file-basics.md)、[已补齐源码的PE实验](pe-heuristic-demo.md)。后者明确是现代教学重建，并区分未命中和解析不完整。

### 3.2 CPU模拟与完整系统沙箱：两条不同实现

**CPU模拟**：扫描器维护虚拟寄存器和内存，解释机器指令，让解密内容出现，再扫描。Symantec的历史回顾记录了1994年前后逐家族检测扩展困难及后续Striker模拟引擎。详见[CPU模拟专题](cpu-emulation.md)。

具体样例中，`14 17 16`逐字节XOR `55`，变成`41 42 43`。预算8条指令时仍是`41 42 16`；第9条才出现ABC。实际解释器与逐步状态已经入库；未知指令、越界和预算耗尽都不是安全结论。

**完整系统沙箱**：程序需要文件、注册表和网络语义时，在带OS的分析环境中运行并监视操作。2007年CWSandbox的作者描述监视DLL与API hooking，实验使用VMware中的Windows XP，不是现代ETW/eBPF采集。包装API时记录参数和返回结果，再汇总报告；[具体包装片段及成功/失败案例](sandbox-api-monitoring.md)。

**局限**：模拟预算、未实现指令、沙箱环境、未覆盖API和不同执行路径都限制观察范围。完整系统环境也不能保证触发全部行为。

### 3.3 HIPS：在真实操作路径上执行策略

**原理**：请求到控制点时，根据主体、目标、已有状态与规则决定继续或拒绝。Cisco 2005年的CSA资料已经包含关联引擎和状态，因此不应把早期HIPS描述成完全没有关联。

**具体例子**：Web服务收到网络输入后请求创建cmd.exe，教学规则拒绝；正常CGI也可能这样工作，因此需要例外和更细上下文。规则返回字符串本身不会阻断，必须接到实际控制路径。[规则、状态变化与反例](hips-stateful-policy.md)。

**局限与下一步**：策略允许的多个行为仍可能组成攻击；拦截日志不一定保留全套调查证据。需要进一步获取现场和过去过程。

## 四、APT、终端遥测与取证（2000s—2013）

**痛点**：清掉一个文件后，仍不知道其他入口、已访问主机和受影响范围。

**必须区分三条路线**：现场快照枚举当前状态；取证分析已有磁盘/内存痕迹；持续事件记录在行为发生时保存通知。它们可以组合，但不能把任意远程取证Agent称作完整事件录像机。

| 证据 | 当时可实现的取得方式 | 不能单独证明 |
|---|---|---|
| 进程和连接 | 远程枚举当前状态 | 已退出短命进程的完整历史 |
| 文件、服务、注册表 | 枚举对象、读取配置 | 文件已执行或启动项已触发 |
| 内存与磁盘痕迹 | 现场采集与解析 | 所有过去行为都可恢复 |
| 事件日志 | 读取已经启用并保留的记录 | 没有采集的字段 |

**落地**：告警触发采集，回传结构化审计结果，分析员提炼IOC，再查询其他终端。2013年的OpenIOC说明展示AND/OR条件：指定服务存在，或同一个文件同时满足bad.exe及4096—10240字节。

**实际例子**：一台主机有bad.exe但大小12000，另一个good.exe大小6000，不能把两者拼成一个满足条件的对象。[XML、匹配代码与测试](remote-forensics-ioc.md)保存具体文件ID。

**局限与下一步**：14:00做进程快照，不会自动补出13:00已退出进程的全过程；其他痕迹或许能辅助。持续记录需要提前部署，随后带来吞吐、留存和调查架构问题。

## 五、EDR 产品架构成熟（2013—2016）

**核心增量**：把采集、身份、存储和查询连接成可持续运行的企业系统，而非发明某一种独立算法。

```text
OS事件 → 驱动/事件接口 → 有限队列 → 用户态服务
→ 本地缓冲/归一化 → 批量传输 → 索引/检索 → 检测/调查/响应
```

### 5.1 Windows事件来源及边界

| 接口 | 作用 | 边界 |
|---|---|---|
| PsSetCreateProcessNotifyRoutineEx | 创建/退出通知与可用上下文 | 创建通知不证明最终执行成功 |
| PsSetCreateThreadNotifyRoutine | 线程创建/退出 | 需要关联进程实例 |
| PsSetLoadImageNotifyRoutine | 映像加载通知 | 不等于完整内存执行观测 |
| ObRegisterCallbacks | 特定对象句柄操作与权限限制 | 不代表全部跨进程内存写入 |
| CmRegisterCallbackEx | 注册表操作通知 | 请求与完成结果要分开 |
| Minifilter | 文件I/O前后处理 | 请求字节数不等于完成字节数 |
| WFP | 分层网络授权、观察与过滤 | 授权不等于连接成功 |
| ETW | Provider发布、Consumer消费 | 不自动提供任意事件或同步否决 |

这些接口有自己的出现时间；进程Ex回调已见于Vista SP1，不是2013年才出现。[回调复制、字段生命周期、文件完成语义及状态查询区别](windows-telemetry.md)给出接口片段；未在本次环境编译驱动。

### 5.2 进程身份与事件归属

使用实例身份做索引、JOIN或图关联，再做模式检测，避免靠时间相近猜测。可用教学键是`host + boot + PID + 创建时间`；稳定传感器ID也可使用，但要验证跨源映射。

例：PID640在10:00属于旧进程、10:03被新进程复用；10:04才到达的10:00:20网络记录仍应归给旧实例。漏采导致多个生命周期候选时保留未知。`ParentProcessId`也不保证等于`CreatingThreadId.UniqueProcess`；记录父关系和实际创建动作要分开。[完整例子与测试](process-identity.md)。

Sysmon的ProcessGuid由Sysmon提供，不是Windows通用进程GUID。当前事件文档可以说明关联设计，但不能把后来Event ID 11等全部倒填给2014年v1。

### 5.3 缓冲、丢失与规模化查询

回调内复制定长数据入队，用户态进行慢I/O、落盘、压缩和发送。示例：4096条队列、生产1000条/秒、消费800条/秒，约20.5秒填满。丢失计数和覆盖区间是调查的一部分，未看到某行为可能是没有采到。[队列代码和容量预算](telemetry-buffering.md)。

2014年osquery把OS状态暴露为SQL表，也支持调度查询与差分；但每分钟查询一次，无法重建10秒创建、12秒退出的进程。这里限定轮询状态例子，不否认后续其他事件能力。[2014发布说明](https://engineering.fb.com/2014/10/29/security/introducing-osquery/)。

## 六、行为关联、AMSI 与 ATT&CK（2016—2020）

### 6.1 AMSI：运行时内容来源

Windows 10在2015年引入AMSI。支持它的宿主在实际解释路径提交内容，安全引擎不必独自还原所有脚本语言。解码文本不等于已经送检，送检也不等于已判恶意；HRESULT和AMSI_RESULT是两层结果。[无害编码样例、接口及失败路径](amsi-runtime-content.md)。

### 6.2 序列检测与CEP

同一进程实例在时间窗内出现“文档父关系的脚本进程记录→网络活动”，可由状态机保存部分匹配。t=0符合创建条件、t=5同实例连接可以匹配；另一进程或超过窗口不匹配。

CEP把分区、部分匹配、超时和跳过策略工程化，不自行学习攻击。EQL在2018年已有公开序列示例。[CEP笔记](cep-event-patterns.md)保留NFA和声明式语义，并链接[实际离线状态机](experiments/event_models.py)。该实验拒绝未重排的乱序输入，并不伪装成有水位线的生产流引擎。

### 6.3 ATT&CK与Sigma各自负责什么

2015年公开的ATT&CK组织战术、技术与过程；它不是传感器或检测算法。工程流程为：攻击行为 → 需要的事件 → 检测逻辑 → 正反例与覆盖验证。

| 技术主题 | 可能需要的观测 |
|---|---|
| 命令与脚本解释器 | 进程、命令行、脚本内容 |
| 进程注入 | 句柄、线程和相应内存相关信号 |
| 自启动 | 注册表、服务/任务配置与执行证据 |
| 凭据访问 | 敏感对象访问及上下文 |

Sigma表达日志条件并转换到查询平台。早期规则可以用EventID、Image、ParentImage等字段；单条规则不会自动获得多步时间状态。ATT&CK技术编号与子技术随版本演进，引用当前编号不等于当年已经采用完全相同分类。

### 6.4 静态机器学习

2018年EMBER公开了静态PE数据和LightGBM提升树基线。文件结构、导入、字节分布等进入分类模型；权重和切分来自样本标签与损失，不是随意人工加分。[两棵树的完整训练逻辑、数值和误报反例](ml-static-detection.md)。

**遗留问题**：采集覆盖不足不会被模型补齐；规则与模型都可能被正常运维触发。未知样本泛化、标签质量、分布漂移与部署误报预算需要独立评测。

## 七、自动响应、XDR 与 eBPF（2020—2023）

### 7.1 自动化调查与响应

微软2018年已经公开自动调查与内存修复；本阶段表示进一步整合，不是首创时间。固定工作流从告警实体读取证据，根据确认的哈希或其他关系扩展范围，生成判定并建立处置任务，不必使用LLM。

```text
告警 → 获取证据 → 扩大调查 → 判定与授权 → 下发任务
→ Agent接收 → OS控制生效 → 回执与效果核对
```

[调查队列与响应状态机](response-automation.md)区分queued、accepted、reported、verified与unknown。只有接收回执不能关闭为已解决；中心分析后隔离是异步响应，不能保证攻击从未执行。

终止进程、隔离文件、网络隔离和清理持久化的影响范围不同，需要审批、回退、身份校验与审计。EDR block mode等产品功能也不代表所有动作都能事前同步阻断。

### 7.2 XDR：跨域实体映射

邮件、用户、终端、网络和云数据需要统一身份与对象语义。相同附件哈希、匹配账号和时间窗口只建立候选投递关系；是否执行以及因果链仍需其他证据。[租户范围、目录映射和候选关联代码](xdr-entity-correlation.md)。

### 7.3 eBPF：Linux采集机制扩展

受验证程序附着于tracepoint/kprobe/LSM等不同接口，提取字段并传给用户态。Linux5.8在2020年增加共享ring buffer；不能将其接口倒填到更早版本。

[exec事件采集片段](linux-ebpf-telemetry.md)展示reserve、字段填充、submit及消费路径。exec替换映像，不自动创建新PID；tracepoint返回值也不表示可阻断。真正防护需要支持决策的hook、正确权限与实际验证。

## 八、AI 辅助调查（2023—2026）

**痛点**：查找、阅读与整理多源证据耗费分析员时间。新增的是交互和调查编排能力，不是基线、图分析或行为规则突然出现。

| 路线 | 历史边界与实现 | 不应推断 |
|---|---|---|
| 统计基线 | 1987年已有审计画像研究；比较指标与历史分布 | 异常必然恶意 |
| 溯源图/图学习 | HOLMES于2019年发表；图遍历与学习是不同机制 | 路径可达等于数据外传，或所有图产品使用GNN |
| LLM辅助 | 2023年Security Copilot提供调查和摘要方向 | 生成叙述可以代替原始证据 |
| 专门Agent | 2025年公告中的专门任务与工具迭代 | 所有EDR已无条件自治隔离 |

[基线与图专题](behavior-baselines-graphs.md)给出数值计算、带时间/对象版本的反查代码与缺边反例。[LLM与Agent专题](ai-assisted-investigation.md)给出查询模板、参数绑定、证据ID与调用历史。

例：只查到P3外联E41，尚未查任务/服务/启动项，应回答“外联有证据，持久化未证实”，不能回答“没有持久化”。查询返回0条、权限不足、超时和遥测未覆盖必须区别记录。模型能建议下一步，执行权限由模型外部控制。

## 九、现代架构与学习实践

### 9.1 四层模型与证据边界

```text
[响应决策] 人工/工作流/受控Agent → 实际OS控制与完成证据
[检测分析] IOC/规则/序列/ML；ATT&CK用于组织攻击知识
[数据关联] 实例身份/归一化/关系/索引/留存
[终端采集] Agent + 回调/ETW/AMSI/文件与网络过滤/eBPF等
```

**发生什么 → 哪些事件相关 → 是否构成攻击 → 应如何处置**。每层都需要把未知和失败传递给上层，而不是将其默认为安全或成功。

### 9.2 最小实验与验证层次

现在仓库有[可运行实验](experiments/README.md)，不再要求运行不存在的pe_heuristic_demo.py：

```sh
python -m unittest discover -s notes/edr/experiments -p 'test_*.py' -v
python notes/edr/experiments/cpu_emulator.py --budget 9
```

实验覆盖掩码扫描、CPU模拟、审计XML、进程实例、离线序列、PE解析与响应状态。实际环境、输出、文件哈希及未验证项目见[验证记录](experiments/validation.md)。构造输入证明逻辑是否正确，不证明真实检出率。

下一层真实传感器实验可以采用Sysmon导出日志再做归一化，或在隔离测试机验证驱动/eBPF；这属于尚未在本次环境完成的系统集成，不应与离线单元测试混淆。生产系统还需抗篡改、权限、可靠更新、跨平台和规模测试。

### 9.3 易错点与演进结论

- EDR不是杀毒软件换名；现代EPP与EDR可以融合，但持续调查与响应是关键增量。
- ETW、内核回调、API Hook的接入点和控制语义不同；AMSI又是宿主主动送检。
- 同一PID、同一路径、同一时间附近不保证同一对象或因果；父关系也不保证实际创建者。
- 行为基线、图分析、机器学习和自动化都有各自历史，不能全归入“2023后AI”。
- 请求不等于成功；告警不等于攻击证实；处置回执不等于完整效果验证。

技术沿三条并行轴累积：判断对象从字节到结构/操作/序列/活动，观测范围从文件到运行时和跨域，响应从本地拒绝到调查、任务执行与受控编排。新能力没有让旧能力失去用途。
