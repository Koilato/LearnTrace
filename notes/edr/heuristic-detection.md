# 启发式检测为什么出现？（原理）

## 一句话
特征码只能识别已知或相近的样本；启发式检测改为检查**可疑结构或行为的组合**，用风险评分提示进一步调查。

## 原理
历史问题：病毒变种、加壳和混淆可能改变已知字节特征 → 文件 Hash 和固定字节签名容易失效 → 需要从结构、执行环境或行为中寻找稳定线索。

静态 PE 启发式示例：
| 信号 | 为什么值得关注 | 局限 |
|---|---|---|
| 节区 Shannon 熵高 | 压缩/加密内容可能让字节分布接近均匀 | 正常软件也可能有高熵数据 |
| 入口点所在节区无执行标志 | 与正常执行需求不一致 | 文件可能损坏或采用特殊装载方式 |
| 同一节区可写+可执行 | 同时修改和执行代码存在风险 | 某些正常程序也可能使用 |
| 可疑 API 导入 | 可能涉及远程进程操作 | 调试器、安全软件同样会用 |

**Shannon 熵**：`H = -sum(p_i * log2(p_i))`，对字节数据的取值一般在 0 到 8 bits/byte 之间；高熵不是恶意证据。

**专家规则**：各信号加权 → 总分达到阈值 → 标记需审核，而不是断言病毒。权重/阈值需要真实样本校准，相关信号可能重复计分。

## 审计
- 先确保 PE 解析正确，再抽取熵、节区权限、入口点位置与导入表。
- 对正常样本/恶意样本分别测误报率与检出率，不能仅用构造样本声称检测有效。
- 加壳是 ATT&CK [T1027.002](https://attack.mitre.org/techniques/T1027/002/) 所记录的一类技术，不意味着必然恶意。

## 易错
- **启发式 ≠ 机器学习**：规则也可以是启发式。
- **加壳 ≠ 恶意**，也不意味着入口点必然不可执行。
- 这是静态文件检测；[EDR 主线](README.md) 进一步加入运行时事件、攻击链关联与响应。
