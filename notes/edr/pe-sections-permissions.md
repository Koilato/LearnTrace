# PE 节区和 R/W/X 权限（概念）

## 一句话
节区（Section）是一块按用途组织的程序内容；节区表记录这块内容的位置、长度及建议的内存访问属性。

## 原理
| 常见名称 | 典型内容 | 典型权限 |
|---|---|---|
| `.text` | CPU 机器指令 | 读+执行（R-X） |
| `.rdata` | 常量、只读字符串 | 只读（R--） |
| `.data` | 已初始化的可写变量 | 读+写（RW-） |

R = read（读取）；W = write（修改）；X = execute（CPU 把这些字节当作指令执行）。

区分两个东西：**Section Table 是目录项；Section Data 才是字节内容**。节区名字并不决定权限，分析权限应读取 `IMAGE_SECTION_HEADER.Characteristics` 中的标志位，如 `IMAGE_SCN_MEM_EXECUTE = 0x20000000`。

## 审计
- 判断某个 RVA 属于哪个节区，再看该节区是否声明为可执行。
- 可写又可执行（RWX）的节区值得进一步检查，但并非恶意证据。
- 可结合节区熵、导入 API、入口点一起做启发式评分，见 [Demo](pe-heuristic-demo.md)。

## 易错
- `.text` 名称不保证一定可执行；其他名字的节区也可能可执行。
- 节区头声明的权限与操作系统映射后的最终页权限可能存在差别。
- 有些数据只占内存、不占文件中等量存储空间，不能把“文件大小”直接看成“内存大小”。
