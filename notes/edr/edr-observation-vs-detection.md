# EDR 行为观测与风险打分不是一回事（原理）

## 一句话
**观测负责取得系统活动证据；关联负责保留对象身份和关系；检测负责判断风险；响应负责执行动作并确认效果。**

## 原理

**先归属，后检测**：采集的进程、网络、文件事件按`HostID + ProcessGuid`或`host + boot + PID + 创建时间`建立实例归属，再做规则、CEP或模型判定。JOIN/Hash Map本身不会知道攻击意图；时间相近不能单独证明因果。

父进程标识可建立**记录父关系**，但未必代表真实创建者。Windows的`ParentProcessId`与`CreatingThreadId.UniqueProcess`是不同字段；缺少实际创建者信息时保留未知，而不是把父关系强行写成创建动作。[实例、迟到记录和父/创建者例子](process-identity.md)。

```text
OS通知、日志或内存证据
         ↓
Agent复制、过滤、缓存（保留来源和丢失信息）
         ↓
按实例/对象版本/时间关联
         ↓
规则 / 行为序列 / 人工评分 / 学习模型
         ↓
告警与调查 → 获准响应 → 核对实际效果
```

以[加壳程序运行时解包](pe-packing-unpacking.md)为例：

| 可能发生的现象 | 观测层可能取得的信号 | 检测层如何使用 |
|---|---|---|
| 启动packed.exe | 进程记录、文件信息 | 建立上下文，保留创建阶段和结果语义 |
| Stub运行 | 入口、模块或可用运行期信号 | 检查是否足以支持执行路径判断 |
| 申请/写入内存 | 依传感器能力取得的相关遥测 | 关联地址范围及结果 |
| 改变内存权限 | 依产品能力取得的保护变化 | 判断是否有RW→RX等转换 |
| 转移到恢复代码 | 执行流或间接证据，不保证采到 | 与此前操作组合，但不能凭缺失日志补造 |

**示例评分，仅教学**：同一区域写入后改变为可执行+20，出现执行迹象+30，其他可疑上下文+10；阈值50则需调查。这些不是厂商权重或恶意概率，相关信号还可能重复计分。已知字节规则、布尔序列和学习模型都可以不用这套人工分数。

### 一条请求与一个成功结果不能互换
文件前置通知“请求4096字节”，只证明请求；完成通知成功且实际2048字节，才支持本次完成2048。网络授权也不自动证明连接建立。接口契约与代码片段见[Windows采集](windows-telemetry.md)。

| 层 | 具体例子 | 该层还不能回答 |
|---|---|---|
| 观测 | E1进程记录、E2网络记录 | 是否恶意 |
| 关联 | 两条记录属于同一实例P3 | 网络动作的攻击意图 |
| 检测 | 文档父关系+60秒内外联命中 | 是否只是正常插件 |
| 调查 | 补充脚本、业务与历史证据 | 响应是否已执行 |
| 响应 | 任务被Agent接受 | 隔离策略是否真正生效 |

[CEP实验](cep-event-patterns.md)验证模式；[响应状态机](response-automation.md)验证回执与完成状态。这些都是有限机制实验，不等于完整EDR产品。

## 审计
- 先问证据来源：回调、ETW、AMSI、文件/网络过滤或其他运行期观测；接口可见性不同。
- 再问归属与覆盖：实例键、对象版本、时间窗口是否可靠，有无[截断、过滤和丢失](telemetry-buffering.md)。
- 再问判定依据：哪条规则、哪项特征、哪个模型或人工证据产生结论；可以怎样解释误报。
- 最后问实际动作：指令、接收、应用和效果验证分别有什么证据，不能用一个“成功”覆盖全部阶段。
- 合法加壳、JIT、正常安装器都是必要反例；申请内存、RW→RX和写启动项不自动构成恶意。

## 易错
- **采集不是风险评分**，评分只是检测方法之一。
- **API调用不保证对应日志存在**；一般EDR不完整记录每次VirtualAlloc、VirtualProtect、内存写入或CPU跳转。
- **静态启发式不同于动态行为分析**：前者不运行样本；二者都可用规则或评分。[实际静态PE实验](pe-heuristic-demo.md)不能监控运行时解包。
- **缺少证据不是排除证据**；没有看到行为也可能是未采集、过滤或丢失。
- **记录父关系不是实际创建者证据；请求、成功和效果是不同层次。**
