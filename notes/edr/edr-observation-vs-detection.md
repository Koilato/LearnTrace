# EDR 行为观测与风险打分不是一回事（原理）

## 一句话
**观测负责获取进程做过什么；关联负责还原操作之间的关系；检测（规则/打分/模型）负责判断风险；响应负责采取动作。**

## 原理

**先归属，后检测**：采集的进程、网络和文件事件先按 `HostID + ProcessGuid`（或 `HostID + PID + 创建时间`）建立进程实例关系；父子进程由父进程实例标识关联。GUID/JOIN/Hash Map 负责确定性事件关联，专家规则、CEP（复杂事件处理）、评分或 ML 才负责判定行为模式及风险；仅凭时间相近不能证明因果。

```text
操作系统事件或内存观测
         ↓
EDR Agent 采集、过滤
         ↓
按进程/时间/上下文关联
         ↓
规则匹配 / 行为序列 / 风险打分 / 机器学习
         ↓
告警与调查（必要时响应）
```

以 [加壳程序运行时解包](pe-packing-unpacking.md) 为例：

| 可能发生的现象 | 观测层可能取得的信号 | 检测层如何使用 |
|---|---|---|
| 启动 packed.exe | 进程创建、文件信息 | 建立进程上下文 |
| Stub 运行 | 入口点/模块/运行时事件 | 结合执行路径调查 |
| 申请/写入内存 | 内存操作相关遥测（依产品能力） | 判断是否存在解包模式 |
| 修改内存权限 | 相关内存保护事件（依产品能力） | 关联 RW→RX 等变化 |
| 转移到恢复代码 | 执行流或其他间接证据（不保证采到） | 与先前事件组合分析 |

**示例评分（仅教学）**：写入后出现可执行权限变化 +20、同一区域出现执行迹象 +30、其他可疑上下文 +10；若阈值为 50，则需调查。这些分数不是厂商真实规则或恶意概率。

**并非必须打分**：
- 单事件规则：发现已知高置信度特征后触发；
- 行为序列：在同一进程上下文内按一定顺序出现多步活动；可由状态机或 CEP 在时间窗内进行模式匹配（详见 [CEP 原理](cep-event-patterns.md)）；
- 评分/模型：综合多个特征输出风险。

## 审计
- 先问“证据从何而来”：Windows ETW/回调、AMSI、文件系统过滤、网络过滤、其他运行时采集；这些机制的可见性不同。
- 再问“关联是否可靠”：事件是否属于同一进程实例，是否有时间窗、丢失事件、误关联。
- 最后问“结论如何产生”：哪条规则、哪个评分特征或模型输出了告警；能否解释误报。
- 用合法加壳程序或 JIT 编译器作负例：申请内存、写入代码和 RW→RX 可能是正常行为。

## 易错
- **采集事件 ≠ 判定恶意**；评分是检测方法之一，不是采集机制。
- **API 调用 ≠ 必然有相应日志**；并非每次 VirtualAlloc、VirtualProtect、内存写入或每次 CPU 跳转都可以被一般 EDR 完整捕获。
- **静态启发式 ≠ 动态行为检测**：前者不运行样本，后者依赖运行期证据；两者均可使用规则或打分。
- 运行时正常解包行为不意味着程序恶意，需要考虑额外攻击上下文。
